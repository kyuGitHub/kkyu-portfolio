금융사 안에 데이터 파이프라인을
직접 깔기

모바일뱅킹 출시 후, 의사결정에 필요한 데이터를 현업이 직접 볼 수 없다는 것이 가장 큰 병목이었습니다. CXM팀을 만들고 사내 첫 클라우드 분석 환경을 도입해 현업이 대시보드를 직접 만드는 단계까지 정착시켰습니다.

역할
CXM팀 신설 · 데이터 플랫폼 리더
기간
2021.03 – 2026.06
도구
AppsFlyer · Amplitude · Tableau
결과
Retention 20% → 35%

문제

마케팅, 상품기획, 개발이 각자의 엑셀과 서버 로그로 따로 보고했고, 데이터 추출 요청은 개발팀에 쌓였습니다. 개발팀장, 상품기획 담당과 함께 문제를 "의사결정에 필요한 데이터를 현업이 직접 볼 수 없다"로 정의했습니다.

클라우드 분석 솔루션은 IT보안·준법·리스크 부서에서 "망분리 위반"으로 보던 사안이었습니다.

판단과 접근

설계 단계에서 규제 리스크를 없애기

  • 이벤트를 추가할 때마다 개발이 필요한 온프레미스 BI 대신 클라우드 SaaS를 택했습니다.
  • 규제 리스크를 심의에서 다투지 않고, 개인정보를 수집하지 않는 이벤트 체계로 설계해 처음부터 없앴습니다.
  • 전자금융감독규정과 클라우드 가이드를 조항 단위로 대조해 위원회 심의 체크리스트를 항목별로 충족했고, 보안성 심의를 통과했습니다.

공통 행동 데이터 체계

  • 이벤트 432개, 속성 241개를 직접 정의하고 비식별 기준을 문서로 만들었습니다.
  • 마케팅·상품·CS·개발 부서를 교육해 현업이 대시보드를 직접 만드는 단계까지 정착시켰고, 사내 스터디 '아이스'(12명)를 운영했습니다.

데이터 파이프라인

보통 컨설팅사와 벤더, 여러 팀이 나눠 맡는 일을 기획자가 직접 했습니다. 도구를 발굴하고 검토해 도입하고, 설치하고 운영하는 전 단계를 맡았습니다.

  • AppsFlyer: 캠페인과 채널별 성과를 하나의 기준으로 묶었습니다. 이후 제휴사 '이어하기' 프로세스에도 전체 적용했습니다.
  • Amplitude: 이벤트 432개, 속성 241개를 직접 정의해 4년 넘게 운영하고 있습니다.
  • Tableau (2025): 부서 인터뷰부터 품의, 서버 설치, 교육, 대표이사 보고까지 도입을 주도했고, 부문 대시보드 4종과 수신 시뮬레이터, MIS를 현업이 쓰는 상태로 만들었습니다(2026).
  • 다음 단계로 클라우드(MS Azure) 도입 검토를 주관하고 사내 세미나를 열었습니다.

배운 점

규제는 나중에 붙이는 조건이 아니라 설계 단계의 제약 조건으로 다룰 때 통과가 쉬웠습니다. "무엇을 수집하지 않는가"를 먼저 정하니 보안·준법 부서와 같은 편에서 이야기할 수 있었습니다.
